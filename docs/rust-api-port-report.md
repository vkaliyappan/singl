# singl-web → singl: full Rust backend port report

Source: `C:\MyFiles\Develop\singl-web` (Next 16.2.9 server app, ~70k lines TS/TSX)
Target: `C:\MyFiles\Develop\singl` (Tauri 2 + Next 16.4.4 static export)
Scope: every API route, server action and server-only module moves to Rust. The UI stays React in the webview.

---

## 1. Summary

| Item | Count | Becomes |
|---|---|---|
| API route handlers (`src/app/api/**/route.ts`) | 51 files, ~3.5k lines | ~60 `#[tauri::command]`s |
| SSE-streaming routes | 15 | Commands that take a `tauri::ipc::Channel<Event>` |
| Server actions (`"use server"`) | 7 files, 44 functions | 44 commands |

**Feasibility:** yes, with no blockers. Every Node dependency has a mature Rust equivalent.
**Estimated Rust size:** 12–16k lines.
**Biggest risks:**
1. The flow engine (expression evaluator shared with the UI, plus the code sandbox).
2. Byte-exact XML round-tripping for TWX entities.
3. Live agent CLI sessions (`agent-live.ts`, 1,070 lines of stream-json protocol handling).

## 2. Target architecture

```
singl/
  src/                         # React UI (static export)
    lib/bindings.ts            # generated by tauri-specta – typed commands + events
  src-tauri/
    Cargo.toml                 # [workspace]
    crates/
      singl-core/              # all logic, no tauri dependency
        src/
          db/       (sqlx pool, migrations, repositories per table)
          secrets/  (keyring)
          twx/      (api client, exporter, deployment-*, connectors, entity-files,
                     entity-migrate, entity-refs, xml parser/format, bundler, run-times)
          flow/     (graph, expression, conditions, schema, datasets, execute, sandbox)
          agents/   (defs, run, live sessions, models, settings)
          assistant/(chats, sessions, domains, protocol)
          repo/     (git ops)
          compare/  (diff tree, content, search)
          fs/       (dir listing, search)
          todos/    (crud, statuses, reminders scheduler)
          notify/   (inbox table + OS notification hook)
          presence/ (teams keeper, Windows only)
          jobs.rs   (job registry, cancellation tokens, progress events)
          workspace.rs (data root resolution, replaces process.cwd())
      singl-cli/               # optional: twx CLI (clap) + MCP server (rmcp) on singl-core
    src/
      lib.rs                   # Builder, plugins, state, scheduler start
      commands/                # thin wrappers: one file per feature, map core errors → IpcError
```

Conventions:
- **Commands** are `async`, return `Result<T, IpcError>`, and take `State<AppState>`. `AppState` holds `SqlitePool`, `reqwest::Client`, the job registry, live agent sessions, and the presence handle.
- **Types** derive `serde::{Serialize, Deserialize}` + `specta::Type`. `tauri-specta` writes `src/lib/bindings.ts`, which replaces both the Drizzle `$inferSelect` types and the hand-written request/response shapes.
- **Streaming:** each former SSE route takes `on_event: Channel<JobEvent>` and returns a `JobId`. `cancel_job(id)` trips a `CancellationToken`. This replaces the `ReadableStream` + `EventSource` pairs.
- **Errors:** `thiserror` in core and one serializable `IpcError { code, message }` at the boundary.
- **Logging:** `tracing` + `tauri-plugin-log` (already present).

## 4. Cross-cutting concerns (do these first)

### 4.1 Workspace root replaces `process.cwd()`
There are 39 `process.cwd()` call sites, all resolving data under the repo checkout:

| Path today | Used by |
|---|---|
| `dist/twx-entities/<env>/…` | entity-files, twx-entities, twx-migrate |
| `dist/repo` | repo routes |
| `dist/twx-run-times.json` | run-times |
| `dist/bundles`, `dist/export`, `dist/extracted`, `dist/temp` | bundler, deployment-* |
| `./WindchillClients/ThingWorx` | exporter, extractor, bundler |
| `backup/<timestamp>` | deployment-backup |
| `scripts/teams-presence-keeper.ps1` | teams-presence (removed by the Rust port) |

A packaged app has no meaningful cwd. Add a **workspace root** setting (stored in `app_settings`, chosen with `tauri-plugin-dialog`), and route every path through `workspace::resolve(Kind)`. For a smooth switch, point it at `C:\MyFiles\Develop\singl-web` so the existing `dist/` data keeps working.

### 4.2 Database
- Location moves from `singl-web/local.db` to `app_data_dir()/singl.db`, with an "import existing DB" command on first run.
- Copy `drizzle/0000…0009.sql` into `singl-core/migrations/`. Drizzle records applied migrations in `__drizzle_migrations` and `sqlx` uses `_sqlx_migrations`, so the importer must stamp the imported DB as fully migrated instead of re-running the files.
- Keep timestamp and boolean encodings identical to Drizzle's (integer mode). Check each `integer({ mode: … })` column in `db/schema.ts`.
- Use `sqlx::query_as!` with offline mode (`.sqlx/`) so builds don't need a live DB.

### 4.3 Secrets
`repo_settings.azurePatToken` and `environment_settings.twxAppKey` are stored in plaintext. Move both to `keyring` (service `singl`, account `twx:<env>` / `azure-pat`) and keep only a "configured" flag in SQLite. App keys never cross IPC back to the UI. Settings shows them masked, and the write path is one-way.

### 4.4 Long-running jobs
There are 15 streaming routes. One generic job layer covers them:

```rust
pub enum JobEvent { Log { line: String }, Progress { done: u32, total: u32 }, Item { .. }, Done { summary: Value }, Error { message: String } }
```

`jobs.rs` registers each job with a `CancellationToken`. When a job finishes, it posts an OS notification if the window is unfocused, replacing the `lib/push` calls that 10 routes make after finishing.

### 4.5 Frontend call-site migration
- 18 files call `fetch('/api/…')`. They become typed `commands.*` calls.
- 15 `EventSource`/stream readers become `Channel` handlers.
- 44 server-action imports become `commands.*`. `revalidatePath` is gone, so refresh local state (zustand/jotai) after each mutation.

## 6. The flow engine: decision required

`lib/twx-flow` splits into two parts.

**UI-shared** (imported by the editor): `types` (13 importers), `expression` (8), `schema` (8), `nodes` (6), `graph` (4), `layout` (3), `conditions`, `agents`, `assistant`, `ids`.

**Server-only:** `execute` (684), `sandbox` (173), `agent-run` (576), `agent-live` (1,070), `agent-models`, `agent-settings`, `assistant-refs`.

`execute.ts` evaluates `expression.ts` templates, `conditions.ts`, and `schema.ts` reshaping, the same code the editor uses for previews and validation. A Rust executor would therefore duplicate ~1.9k lines of semantics.

| Option | How | Pros | Cons |
|---|---|---|---|
| **A. Rust executor + Rust evaluator** | Port graph, expression, conditions, schema and datasets to Rust. The UI keeps TS copies for editing, plus a `flow_preview_expression` command for authoritative previews. | Everything native; one sandbox story | Two implementations that can drift. Needs a shared golden test corpus (JSON fixtures run by both `cargo test` and vitest). |
| **B. Rust orchestrator, TS evaluator in QuickJS** (recommended) | Rust owns the run loop, TWX calls, agent nodes, cancellation and events. Pure evaluator modules (`expression`, `conditions`, `schema`, `datasets`, `graph`) are bundled with esbuild into one JS file that is embedded with `include_str!` and called through `rquickjs`. | One source of truth for expression semantics; less to port | Two JS contexts: a trusted evaluator and an untrusted user sandbox (see below). Evaluator calls cross a JSON boundary. |

**Code node sandbox:** replace `isolated-vm` with `rquickjs`. For each run:
- `Runtime::set_memory_limit(CODE_MEMORY_LIMIT_MB)` and `set_interrupt_handler` with a deadline. This covers both sync loops and the "never-settling await" case that the current code handles with its own timer.
- Keep the same `PREAMBLE` wrapper and JSON-envelope in/out. The snippet still sees no fetch, fs or app key.
- Rewrite the error-frame regex `<isolated-vm>:(\d+):(\d+)` for QuickJS stack format.
- Semantics shift from V8 to QuickJS. Run every saved flow's Code nodes from `service_flows` through both engines before switching over.

## 12. Risks

| Risk | Impact | Mitigation |
|---|---|---|
| XML output differs from TS formatter | Noisy diffs and broken deploys | Golden-file tests before any write path ships |
| V8 → QuickJS behaviour in Code nodes | Saved flows break | Run all stored Code nodes through both engines; report diffs |
| Expression semantics drift (option A) | UI preview ≠ run result | Option B, or a shared fixture corpus |
| Agent CLI protocol changes (claude/codex/copilot/agy) | Assistant breaks | Keep the per-provider defs data-driven as in `agents.ts`; one parser module per provider |
| Orphaned child processes | Leaked CLIs | Job Object with `KILL_ON_JOB_CLOSE`; kill all on app exit |
| DB import from Drizzle migration table | Migrations re-run or fail | Importer stamps `_sqlx_migrations` after checksum verification |
| Secrets in existing `local.db` | Plaintext keys remain | Import moves them to keyring and blanks the columns in the new DB |
| Mobile targets (icons exist) | git, spawn and presence don't exist there | `#[cfg(desktop)]` on those commands; the UI hides those features |
| Next 16.4 breaking changes vs 16.2 | Page ports fail | Read `node_modules/next/dist/docs/` first (AGENTS.md) |

## 13. Decisions needed before phase 0

1. **Flow engine:** option A (all Rust) or option B (Rust orchestrator + TS evaluator in QuickJS). The recommendation is B.
2. **Git:** shell out to `git` (recommended) or `git2`.
3. **Workspace root:** point at the existing `singl-web` folder, or move `dist/` + `WindchillClients/` into a new location.
4. **CLI/MCP:** port to Rust, or keep `cli.ts`/`mcp.ts` in TS against the new DB path (they read `environment_settings`, and app keys will move to keyring).
5. **Targets:** Windows desktop only, or keep macOS, Android and iOS in scope.
